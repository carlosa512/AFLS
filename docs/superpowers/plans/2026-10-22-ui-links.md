# One name, one link — implementation plan (PR 1 of the UI consistency spec)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every player name and every team name in the UI is rendered by one shared component that opens his card or the team's page, and every team dropdown is the shared picker.

**Architecture:** Two components, `PlayerLink` and `TeamLink`, go into `src/ui/components.tsx` next to `TeamChip` and `PlayerAvatar`. The nav context moves to its own file so `components.tsx` can use it without importing `App.tsx`. Every hand-rolled link is replaced call site by call site; `TeamLabel` and the private copies in `Stats.tsx`, `FrontOffice.tsx` and `mail.tsx` are deleted. A grep test in `src/ui/ui.test.ts` keeps raw names out of screens from now on.

**Tech Stack:** React 18, TypeScript, Vitest (no DOM: UI tests render with `renderToStaticMarkup` and assert on markup).

**Spec:** `docs/superpowers/specs/2026-10-22-ui-consistency-design.md`, section "PR 1 — One name, one link".

## Global Constraints

- No visual change beyond what the spec names: the link keeps class `linklike`, tables keep `player-link` (avatar + underlined name) and `team-inline`.
- Names come from `playerName` / `shortName` in `src/ui/format.ts`; never build `${firstName} ${lastName}` inline.
- Fog of war is untouched: the components render names only; `Ovr` and friends stay at the call sites.
- `npm run format` before each commit; `npm run typecheck` and `npx vitest run src/ui` must pass before each commit.
- Version: last number only (`0.1.4` → `0.1.5`) in the final task, with a line under MVP item 14.

## Review Focus

1. A free agent or prospect (`teamId === null`) in a table: the avatar must render in the free-agent grey, not throw. Pinned in Task 1's test.
2. A player with a one-letter first name or a hyphenated surname: `short` must still read "J. Smith-Jones". Covered by `shortName`, asserted in Task 1.
3. A team link in a sentence (Home's "at the Dallas Rangers") must not draw a chip; `chip` defaults off. Pinned in Task 4's test.
4. The trade partner picker must never offer the user's own club; the draft history and the trade history must offer "League". Pinned in Task 6's test.
5. Deep links: the `sub` text under a team (record, "Division leader") stays outside the button so a screen reader reads the link as the team name only. Pinned in Task 4's test.

```tsx
export function PlayerLink({
  league, player, avatar, short = false, pos = false, bold = false, className,
```

```ts
import { readdirSync, readFileSync } from 'node:fs';
import { join } from 'node:path';

describe('screen contract', () => {
  const files = ['src/ui', 'src/ui/screens']
    .flatMap((d) => readdirSync(d).filter((f) => /\.tsx$/.test(f) && !/\.test\./.test(f)).map((f) => join(d, f)))
    .filter((f) => !f.endsWith('components.tsx'));
  const src = (f: string) => readFileSync(f, 'utf8');
  it('renders player names only through PlayerLink', () => {
    const allowed = ['src/ui/screens/PlayerCard.tsx', 'src/ui/negotiation.tsx', 'src/ui/screens/GameViewer.tsx'];
    const bad = files.filter((f) => !allowed.includes(f) && /\{\w+\.firstName\} \{\w+\.lastName\}/.test(src(f)));
    expect(bad).toEqual([]);
  });
  it('renders team names only through TeamLink', () => {
    const bad = files.filter((f) => /<TeamLabel|className="linklike[^"]*" onClick=\{\(\) => nav\.openTeam/.test(src(f)));
    expect(bad).toEqual([]);
  });
  it('builds team dropdowns only with TeamPicker', () => {
    const bad = files.filter((f) => /\[\.\.\.league\.teams\]\s*\.sort/.test(src(f)));
    expect(bad).toEqual([]);
  });
});
```

`allowed` names the three places a name is not a link by design: the card's own header, the "signed" toast, and the play-by-play parser (it links by index). Add a one-line comment saying so.
