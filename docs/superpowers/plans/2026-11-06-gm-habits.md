# GM Habits and Archetypes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AI GMs carry hidden habits that form and fade through a marble bag, each leaning one existing decision, and you read them only through clues in words (SNN, his card, your director).

**Architecture:** `gmHabits.ts` holds the registry, storage on `GeneralManager`, the bag and the log, and the one read every hook uses (`habitOn`); `gmHabitsYear.ts` resolves the log into marbles and draws at the new league year; `gmVoice.ts` turns dials and the log into words through `voice.ts`'s `say`. Hooks are one-line leans in `offseason/ai.ts`, `offseason/draft.ts` and `trade/`; a new `npm run gm-habits` check measures the bag and each lean.

**Tech Stack:** TypeScript, Vitest, the engine's seeded `Rng`, `voice.ts` banks, React screens.

**Spec:** `docs/superpowers/specs/2026-11-05-gm-habits-design.md` (research in `docs/research/front-offices.md`).

## Global Constraints

- No screen or mail shows an archetype name, a habit name, a grip, a marble or a dial as a number (spec §4). Your own GM never has habits.
- Engine code never uses `Math.random`; every draw here comes from `${seed}:${season}:gm-habits:${gmId}` or `${seed}:gm-habits:start:${gmId}`, and moves no other stream.
- `League` stays plain JSON: new fields are optional; `SAVE_VERSION` 88 → 89 with a `migrate.ts` step.
- Leans are small and read through `habitOn`/`gunShyAt` only; a hook never reads `gm.habits` itself.
- `npm run trades` and `npm run offseason` stay green with no range loosened. A seed-pinned test that an archetype reshuffle breaks picks a new seed.
- `npm run format` before every commit; markdown is not formatted. Commit messages end with the attribution lines the session gives.
- Names (`HabitId`, labels) stay inside the engine, docs and tests.

## Review Focus

1. A GM between jobs (`gm.teamId === null`): the new-year step must resolve his log and keep his marbles without drawing, and `aiGm` must return nobody for a vacant club → Task 3 tests it.
2. The user takes over a club whose AI GM had habits, or is fired and an AI GM arrives: `habitOn` is false for the user's club whatever the GM record holds, and the user's own GM record never gains habits → Task 1 and Task 3 test it.
3. An old save with GMs who have no `habits` loads mid-season and a trade runs before any new year: `logMove` on a GM with no log, `bagOf` on a GM with no marbles → Task 1 tests undefined fields.
4. A pattern line or card line about a GM whose logged player has retired or been pruned (`league.players[id]` missing): the voice must skip the fact, never crash → Task 9 tests it.
5. The early-extension pass on a club already over next year's books, or with a player whose rookie deal is in year two: nothing signs, nothing logs → Task 6 tests it.

  ```ts
  export interface HabitHold { grip: 1 | 2 | 3; pos?: Position }
  export interface HabitMove { habit: string; season: number; teamId: number; playerId?: number; pos?: Position;
    /** The move's own terms met the + condition (a sale that brought back a round 1–2 pick). */ good?: true;

  // on GeneralManager:

  ```

Rules the signatures leave open, pinned here:
- `habitOn`: false when `habitsForce.off`; `id === habitsForce.all` when `habitsForce.all` is set; false for `team.id === league.userTeamId` or `team.gmId === null`; else `gm.habits?.[id]?.grip >= ACTIVE_GRIP`. `gunShyAt` is the same with `habits.gunShy.pos === pos` (forced: `habitsForce.pos`).
- `draftedBy`: `p.draft` exists and some appointment `a` has `a.teamId === p.draft.teamId` and `a.start.season - (a.priorSeasons ?? 0) <= p.draft.season` and `(!a.end || a.end.season >= p.draft.season)`.
- `startHabits`: no-op if `gm.habits` exists or `gm.id === league.userGmId`; `STARTING_HABITS[archetype][0]` at grip 2; Balanced: `new Rng(`${league.seed}:gm-habits:start:${gm.id}`).pick(HABIT_IDS without 'gunShy')`.
- `logMove`: no-op when `aiGm` gives nobody; pushes `{ habit, season: league.season, teamId: team.id, ...extra }`; drops entries with `season < league.season - LOG_YEARS`.
- `bagOf`: `BLANKS` blanks (`BLANKS_OLD` at `gm.age >= OLD_AGE`), two marbles per `STARTING_HABITS[archetype]` entry (Balanced: one per habit but gunShy), plus `habitMarbles` counts.
- `drawHabits`: `rng.shuffle([...bagOf()]).slice(0, DRAWS)` in order; a habit marble is grip +1 (new at 1), capped at 3; a fade marble is grip −1 (delete at 0, nothing for an unheld habit); a draw that would make a fourth habit reach grip 2 stays at 1; then `delete gm.habitMarbles`. A `gunShy` marble raises the grip of an existing `gunShy` hold (which carries `pos`) and does nothing when there is none: the habit forms only in `noteRelease`.
- `noteRelease`: when `aiGm` gives a GM, `dead >= BLOWUP_SHARE * league.caps[league.season]`, `p.contract.signedSeason` falls inside his current appointment (`start.season <= signedSeason`) and `p.contract.signedWeek !== -1`: set `habits.gunShy = { grip: max(existing grip, 1), pos: p.position }`, `addMarbles(gm, 'gunShy', GUN_SHY_MARBLES)`, `logMove(..., 'gunShy', { playerId, pos })`.
- `usedThisYear`: a log entry of that habit with `season === season`, or `habitMarbles[id] > 0`.

### Task 4: Outcomes into marbles (`resolveMoves`)

**Files:**
- Modify: `src/engine/gmHabitsYear.ts`
- Test: `src/engine/gmHabitsYear.test.ts`

**Interfaces:**
- Produces: `export function resolveMoves(league: League, gm: GeneralManager): void` and `export function noteYoungQbSeasons(league: League): void` (called by `habitsNewYear` before resolving). Helpers it may import: `seasonRole` (`scouting.ts`), `seasonAwards` (`awards.ts`), `playerOvr` (`positions.ts`), `league.history`.
- Each unresolved entry `e` (season `s`, `now = league.season`, `p = league.players[e.playerId]`) is judged by the table; `verdict` 1/−1 adds one marble to `e.habit` or `fade:${e.habit}`; `e.resolved` is set to the verdict (0 for no marble); `null` means not due yet. A missing `p` resolves 0.

| habit | due (now − s ≥) | +1 | −1 |
|---|---|---|---|
| bridgeQb | 2 | `p` (the young QB) on `e.teamId` and `seasonRole(league, p, s+1)?.role === 'starter'` | otherwise |
| tradeUpQb | 1 | starter in `s` (then resolved) | gone from the club; at due 2 not a starter in `s+1` either |
| extendEarly | 3 | on the club and starter in `s+2` | otherwise |
| sellsEarly | 2 | `e.good` and no All-League | All-League team (`seasonAwards(league, s or s+1)?.allLeague` flat) for another club in `s` or `s+1` |
| hisGuys | 1 | on the club and starter in `s` | gone from the club |
| firstsForStars | 1 | `league.history.find(h => h.season === s)?.playoffs?.[e.teamId]` | otherwise |
| swaps | 1 | always | never |
| bpa | 2 | starter in `s` or `s+1` (then resolved) | at due 3, not a starter in `s+2` |
| tagsFirst | 2 | still on the club | gone |
| youngQb | 1 | `playerOvr(p) >= e.ovr + 0.5` | gone, or his third unresolved-0 entry in a row |
| gunShy | 1 | never (marbles came at formation) | never |

- `noteYoungQbSeasons`: for each AI club with a GM, each QB with `age <= 25` (after the year's `p.age++`, so read `age <= 26`), `draftedBy(gm, p)`, `seasonRole(league, p, last)?.role === 'starter'` and the club's `league.history` record for `last` under .500 → `logMove(league, team, 'youngQb', { playerId, ovr: playerOvr(p) })`. Set `e.season = last` on that entry (the move belongs to the season just played).
