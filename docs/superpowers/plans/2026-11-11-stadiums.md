# Stadiums: a building for every club — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every club plays in its own building in the broadcast view: a bowl with depth seen through one camera,
with its roof, its city outside and a crowd that follows the record.

**Architecture:** One painter (`src/ui/stadiums/`) draws a building from a description onto a small drawing
surface (`Pen`), so the same code paints a canvas in the game, a review page for the owner, and a recorder in the
tests. The broadcast view's straight-line map is replaced by the painter's camera, so the field's paint and the play
sit in the same space as the building. The painter is written once, in the repo, and is connected to no screen
until the owner says "build it".

**Tech Stack:** TypeScript, React, Canvas 2D, Vitest (`renderToStaticMarkup`), esbuild (already here through
Vite) for the review pages, Playwright for the look and the timing.

**Spec:** `docs/superpowers/specs/2026-11-11-stadiums-design.md` (approved Nov 11; binding). The approved drawing
code is `docs/superpowers/specs/2026-11-11-stadiums-prototype.html`: tasks 1 to 5 port it, they do not redesign it.

## What the spec assumed, checked

The owner asked for the spec's assumptions to be doubted. Four did not hold as written, and this plan builds the
corrected version of each.

1. **"A building is data, not code" is only half true.** The record a club has is data. But the 37 ideas need about
   twenty things drawn in space (masts, towers, a spire, baffles…) and about a dozen kinds of land (marsh, a lake
   with docks, rail yards, houses, desert…). That drawing is the bulk of the work, and it is code. Each division
   task below names the new parts it needs.
2. **"Reviewed before any game code" would mean drawing everything twice** (once on throwaway pages, once in the
   game), and the two would drift. So the drawing code is written once, in the repo, and the owner's review pages
   are built from it. What waits for "build it" is connecting it to the game: until then no screen imports it and
   nothing a player sees changes. This rewords spec Decision 11; the owner's gates stay where they were.
3. **The speed budget fails as first drawn.** Measured on the approved pages: 43–79 ms a building at desktop speed,
   but 303–390 ms with the processor slowed six times (a mid-range phone). The spec's limit is 300 ms. Task 6
   fixes it (seats drawn in batches by colour) and adds a timing command that fails over the limit. Painting also
   happens under the pregame card, so a player never waits on it.
4. **Three things the owner has not seen yet:** a real play on the smaller field at phone size, a night game, and
   rain or snow with no sky. All three are assumptions until looked at. Task 7 shows them, before 32 more
   buildings are drawn.

Three more are kept as the spec has them, with the doubt recorded:

- **Settings from memory.** Each real ground's surroundings were written from memory and some are shaky. Every
  division task checks them and marks any it could not confirm on the owner's page.
- **A neutral-site final in the home club's building** will look like a home game. The spec's default stands; a
  neutral building is a later pass.
- **A dome's game has no "night"** in its weather (indoors has no sky). The land round it uses the kickoff slot
  (`isNight`) instead.

## Global Constraints

- **Screens only.** No file under `src/engine/` changes. Nothing is added to `League`, `Game`, `GameResult` or the
  save. No `SAVE_VERSION` bump. No tuning number moves.
- **Not connected until "build it".** Tasks 1 to 16 add files under `src/ui/stadiums/`, a script and tests. No
  file outside that folder imports from it before Task 17. Task 17 starts only on the owner's word.
- **The owner's gates:** Task 7's page, each division's page (Tasks 8 to 16), then "build it". A task with a gate
  is not finished until the owner has answered.
- **Original work only.** No real stadium and no real landmark is copied. A setting follows the lie of the land
  round the real ground (downtown, out of town, on a river) and nothing more.
- **People are drawn only in the stadium.** No figures in windows or on streets.
- **One camera.** Everything in the broadcast view goes through `toFrame`. All-22 is untouched.
- **No `Math.random`.** Every draw comes from the engine's seeded `Rng`, keyed by the club.
- **Speed:** one building paints in 300 ms or less with the processor slowed six times (`npm run stadiums --
  --time`).
- **Reduced motion:** nothing in the picture moves; the cheer's brightening is off under
  `prefers-reduced-motion`.
- **Checks:** `npm run typecheck`, the tests touched, `npm run format`. No sims, no `npm run check`.
- **No pull request** until the owner asks. Commits go to `claude/modest-keller-viipnh`; bring `main` in before
  each page goes to the owner. Version `0.4.29` → `0.4.30` in Task 20, one changelog entry (title ≤ 40
  characters, text ≤ 200, at most two sentences).

## Review Focus

1. **A replay of an old game after the club has moved.** Tennessee's 2026 game watched in 2028 must show the
   stockade, not the barn: the building is the game's season's, never today's. Test in Task 16 and Task 19.
2. **A roof that shuts during a game** (rain from the third quarter). The picture changes at the quarter, and never
   while a play is running. Test in Task 19.
3. **A record that is no record:** week 1 (0–0), a tie, the first three home games, a playoff game. Turnout must be
   Even at 0–0, count a tie as half a win, never drop below Even early, and be full in the playoffs. Test in
   Task 2.
4. **A league the list does not know** (a mod's abbreviations) or a club in near-black or near-white. It gets the
   plain bowl in its own colours, and the crowd can still be told from the seats. Test in Task 5.
5. **The picture and the play out of step on a narrow screen.** The canvas and the SVG over it must share one box
   at every width, or the stands slide over the field. Test in Task 18, and the look in Task 20.

### Task 3: The stands, the crowd and the roofs

**Files:**
- Create: `src/ui/stadiums/types.ts`, `src/ui/stadiums/paint.ts`, `src/ui/stadiums/stands.ts`,
  `src/ui/stadiums/roof.ts`
- Test: `src/ui/stadiums/stadiums.test.ts`

**Interfaces:**
- Consumes: Tasks 1 and 2.
- Produces (in `types.ts`):
  - `interface Look { night: boolean; precip: 'none' | 'rain' | 'snow' | 'mixed'; roof: 'none' | 'open' |
    'closed'; fill: number }`
  - `type Rim = { kind: 'flat'; h: number } | { kind: 'peaks'; h: number; rise: number; every: number }` (more
    kinds are added by the division that needs them)
  - `interface Canopy { kind: 'canopy'; d0; d1; y0; y1: number; skin: string }`
  - `interface Slab { kind: 'slab'; profile: Profile; th: number; skin: string; section: string; rib?: string;
    edge?: string; opening?: { x0: number; x1: number; z1: number }; leaves?: { xi; xo; yi; yo; th; z1: number;
    skin: string } }`, `type Profile = { kind: 'flat'; h: number; crown: number; fall: number } | { kind: 'canoe';
    ends: number; rise: number; back: number }`
  - `interface Building { id: string; decks?: Deck[]; rim: Rim; openEnd?: 'left' | 'right'; seat: string; chair?:
    string; wall: string; wallGlass?: boolean; windows?: string; face?: string; plaza?: string; ground: string;
    roof?: Canopy | Slab; features: FeatureUse[]; setting: SettingUse }`. Here `SettingUse` is `{ kind: 'none' }`
    and `FeatureUse` is `never`; Task 4 widens both.
- Produces (in `paint.ts`): `paintStadium(pen: Pen, b: Building, colors: [string, string], look: Look, seed:
  string): void`, in this order: the land (Task 4), the plaza, the ground inside the bowl, the features behind
  the stands, the back wall, the decks from the top down (bank, rows and seats, stairs and tunnels, face and rail,
  the gap under a deck), `pen.flush()` after each deck, rim lights or the canopy, the slab, the features in front.
- Rules the tests pin: a seat is drawn as a dot when taken and a box when empty; each seat makes two draws from
  `new Rng(seed + ':crowd')` whatever the fill, so a seat taken at a lower fill is taken at every higher one; with
  `look.roof === 'closed'` a slab's opening is drawn shut; with `'none'` on a building that has a slab the slab is
  still drawn (a dome's weather has no roof state).
