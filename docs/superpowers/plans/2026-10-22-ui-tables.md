# Draft and trades on the house widgets — implementation plan (PR 2 of the UI consistency spec)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every list of comparable rows sorts through the one sort header with the roster's column names, marks your row with one class, and the trade screen's views are routed tabs like the Front Office's.

**Architecture:** The trade screen's five views become a `sub` segment on the office route (`#/office/trades/<sub>`), parsed in `routes.ts` and navigated with `nav.go`. Static tables (Standings, Playoffs history, Finances' contracts, the re-sign tables, the league grades tables) get `useSort`/`SortTh`; the two checkbox lists that are not tables (trade assets, your block) get a small `SortSeg` control that shares `SortState`. `tr.me` goes; `tr.is-user` is the one mark. Stats' "Whole league / Your roster" select becomes the same `seg` control the office tabs use.

**Tech Stack:** React 18, TypeScript, Vitest (markup via `renderToStaticMarkup`, grep tests in `src/ui/ui.test.ts`).

**Spec:** `docs/superpowers/specs/2026-10-22-ui-consistency-design.md`, section "PR 2 — Draft and trades on the house widgets". Builds on PR 1 (`PlayerLink`, `TeamLink`, `TeamPicker`, `nav.ts`).

## Global Constraints

- Column vocabulary (from the Roster): `Player`, `Pos`, `Age`, `OVR`, `Stars`, `Cap hit`, `Thru`. Screen-specific columns keep their names (`Your grade`, `Ceiling`, `Ask`, `Market`, `% of cap`, `APY`).
- One row mark: `tr.is-user`. `tr.me` is deleted from `styles.css` and every screen.
- Fixed-order tables stay fixed: box scores, Schedule, Compare, the depth chart's default view.
- Fog of war untouched: sorting reads what the screen already shows (`seenOvr`, perceived values), never `player.ratings` or `playerOvr`.
- `npm run format` before each commit; `npm run typecheck` and `npx vitest run src/ui` green before each commit.
- Version: last number only (`0.1.5` → `0.1.6`) in the final task, one line under MVP item 14.

## Review Focus

1. A deep link `#/office/trades/block` opens the block view; `#/office/trades/nope` and `#/office/fa/block` are rejected (null), not silently reinterpreted. Pinned in Task 1.
2. A counter-offer or "Ask their price" from a player card must still land on the trade table with the draft loaded, now via navigation. Pinned in Task 1's test on `defaultTradeTab`.
3. Standings sorted by a column must keep each division's own rows (no cross-division mixing) and the "Division" header must return to the tiebreaker order. Pinned in Task 3.
4. Sorting a table whose rows carry a form (Negotiate, Tag, Decline buttons) must not lose the buttons or their disabled state: the row is sorted, not rebuilt. Pinned in Task 4 by asserting the button count before and after.
5. Your row in the league grades table must open its staff when tapped, as before, with the new class. Pinned in Task 5.

export function SortSeg<K extends string>({ options, sort, onSort, label }: {

## Deviations from the spec, decided here

- The spec lists "Finances' league cap table"; Finances has no league table, only the team's contracts table, which is what sorts.
- The spec names "trade table assets and the offers list" for `SortTh`; both are checkbox lists without a header, so they get `SortSeg` (same state, list-shaped control).
- `.is-user-text` stays: it marks a name in a sentence, not a row.
- The draft history's team picker sits in a `Section` (no action slot) and stays where it is.
